# API Reference

All endpoints are consumed **through the gateway**: `http://localhost:8080` locally.
There is no other supported entry point — services are only reachable directly on their
own ports for local debugging/testing, never in a deployed environment.

## Authentication

Every route except `/auth/**` and `/actuator/**` requires:

```
Authorization: Bearer <accessToken>
```

The gateway validates the JWT, then injects `X-User-Id` and `X-User-Roles` headers for
the downstream service — **any client-supplied copies of these headers are stripped**,
so they cannot be spoofed (see `docs/Security.md`). Downstream services read the caller's
identity from these headers; they never re-validate the token.

## Discovering the full contract

There is currently **no OpenAPI/Swagger UI** (no `springdoc-openapi` dependency in any
module — verified against every `pom.xml`). Until that's added (tracked in
`ROADMAP.md`), the source of truth is:
1. This document + `docs/Backend.md` (hand-maintained, generated by reading every
   `@RestController`).
2. The Postman collections in [`postman/`](../postman) — `Athena.postman_collection.json`
   (V1), `Athena-V2.postman_collection.json`, `Athena-V3.postman_collection.json`. Note
   these predate `rag-service`, the Daily Journey, and several `auth-service` endpoints
   (2FA, devices, export) — they are historical snapshots, not a live contract.

## Error contract

Every service shares `athena-common`'s `GlobalExceptionHandler`, so every error response
has the same shape:

```json
{
  "timestamp": "2026-06-12T10:15:30Z",
  "status": 400,
  "error": "Bad Request",
  "message": "Validation failed for one or more fields",
  "path": "/users",
  "details": [{ "field": "age", "message": "age must be at least 5" }]
}
```

AI-backed endpoints (`ai-service`, `rag-service`) return `503` — never a bare `500` —
when the local LLM is unreachable, with `{"status":"TEMPORARILY_UNAVAILABLE", ...,
"retryAvailable": true, "retryId": "..."}`; the request can be retried via
`POST /ai/retry/{requestId}`.

## Example end-to-end flow

```bash
BASE=http://localhost:8080

# 1) Register (multipart; image is optional)
curl -s -X POST $BASE/auth/register -F email=ada@example.com -F password=Password123!

# 2) Log in
RESP=$(curl -s -X POST $BASE/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"ada@example.com","password":"Password123!"}')
TOKEN=$(echo "$RESP" | jq -r .accessToken)

# 3) Onboarding runs automatically on registration (via UserRegisteredEvent) —
#    fetch its state directly:
curl -s $BASE/ai/onboarding/me -H "Authorization: Bearer $TOKEN"

# 4) Submit a goal, then an assessment, to get a roadmap + daily plan
curl -s -X POST $BASE/ai/onboarding/goal -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"goal":"Become a backend engineer"}'

# 5) Today's adaptive learning day
curl -s $BASE/daily-journey/today -H "Authorization: Bearer $TOKEN"
```
